## Why use Poudriere instead of NanoBSD?

BSDRP uses a heavily customized NanoBSD script that includes package generation. This code has to be adapted every time the port build infrastructure changes.

Why not use the newer "poudriere image" feature and avoid reinventing the wheel?

## Understanding Poudriere image

### What is Poudriere?

It is a shell script that builds packages in a clean (jail) environment. Once you have a clean jail on one side and a list of freshly generated packages on the other, why not mix them together in a NanoBSD-like firmware?

This is the "poudriere image" feature, included in poudriere-git-3.3.99.20220713 and presented here.

### Images generated by Poudriere

Poudriere can generate multiple image types (the default is `iso+zmfs`):

- `iso`: ISO 9660 format image
  - `iso+mfs`: ISO 9660 variant where the root filesystem is MFS mounted
  - `iso+zmfs` (default): ISO 9660 variant where the root filesystem is LZ77 compressed and MFS mounted
- `usb`: GPT-layout UFS2 image with a UEFI boot loader
  - `usb+mfs`: variant where the root filesystem is MFS mounted
  - `usb+zmfs`: variant where the root filesystem is LZ77 compressed and MFS mounted
- `rawdisk`: raw UFS2, softupdates-enabled disk image
- `zrawdisk`: raw ZFS disk image
- `tar`: XZ-compressed tarball
- `firmware`: NanoBSD-style image with GPT partitions and a UEFI boot loader
- `rawfirmware`: raw disk image (update image that includes only one system partition of the firmware?)
- `embedded`: u-boot-ready embedded image
- `zsnapshot`: full and incremental ZFS snapshots to be used in a jail

### The six minimum steps to build a Poudriere firmware image

Using Poudriere on ZFS is not mandatory, but strongly advised.

1.  Install Poudriere and configure it:
        sudo pkg install poudriere-devel
        echo "ZPOOL="`zpool list -H | cut -f1` | sudo tee -a /usr/local/etc/poudriere.conf
2.  Create a Poudriere jail with a GENERIC kernel (by default, the kernel is not built or installed), here named "router":
        sudo poudriere jail -c -j router -v 15.0-RELEASE -K GENERIC
3.  Create a port tree using `poudriere ports`:
        sudo poudriere ports -c -p router_ports
4.  Generate the list of ports to be built and added to the firmware image:
        cat > ~/router-pkglist <<EOF
        sysutils/tmux
        net/frr10
        net/bird2
        net/mpd5
        EOF
5.  Build the ports (that is, generate binary packages) from the corresponding jail using `poudriere bulk`:
        sudo poudriere bulk -j router -p router_ports -f ~/router-pkglist
6.  Generate the disk image (4 GB total: two system partitions of 2 GB each) using `poudriere image`:
        sudo poudriere image -t firmware -j router -s 4g -p router_ports -h router -n router -f ~/router-pkglist
        (...)
        [00:00:15] Creating ESP image
        [00:00:15] ESP Image created
        [00:00:21] Image available at: /usr/local/poudriere/data/images/router.img

### Comparing a Poudriere firmware image with a NanoBSD image

#### Final firmware file size

Check the Poudriere firmware file size:

```
# ls -alh /usr/local/poudriere/data/images/router.img
-rw-r--r--  1 root  wheel   3.8G Jul 22 19:24 /usr/local/poudriere/data/images/router.img
```

We get a 3.8 GiB disk image, which fits onto a [marketed-size 4 GB flash disk](https://github.com/freebsd/poudriere/pull/638).

#### Partition scheme

The resulting image partition layout behaves the same as a NanoBSD image:

- 10 M GPT partition with the EFI bootloader (NanoBSD uses an MBR scheme with a BIOS bootloader)
- First 991 M (calculated from user input) system partition, called `gpt/${IMAGENAME}1`
- Second system partition, called `gpt/${IMAGENAME}2`
- Configuration partition (hard-coded to 32 M), called `gpt/cfg`
- Data partition (hard-coded to 32 M), called `gpt/data`

#### /etc RAM disk

The Poudriere image correctly matches the NanoBSD `/etc` and `/var` ramdisk layout:

```
root@router:~ # mount
/dev/gpt/router1 on / (ufs, local, read-only)
devfs on /dev (devfs, local, multilabel)
/dev/md0 on /etc (ufs, local)
/dev/md1 on /var (ufs, local)
```

Compared with a standard NanoBSD:

```
[root@nanobsd]~# mount
/dev/ufs/NANOs1a on / (ufs, local, read-only)
devfs on /dev (devfs, local)
/dev/md0 on /etc (ufs, local)
/dev/md1 on /var (ufs, local)
```

#### fstab

Poudriere's `fstab` uses GPT labels, while NanoBSD's uses UFS labels:

```
root@router:~ # cat /etc/fstab
/dev/gpt/router1 / ufs ro 1 1
/dev/gpt/cfg  /cfg  ufs rw,noatime,noauto        2 2
/dev/gpt/data /data ufs rw,noatime,noauto,failok 2 2

[root@nanobsd]~# cat /etc/fstab
/dev/ufs/NANOs2a / ufs ro 1 1
/dev/ufs/NANOs3 /cfg ufs rw,noatime,noauto 2 2
/dev/ufs/NANOs4 /data ufs rw,noauto,failok 2 2
```

## Migrating from NanoBSD to Poudriere image

### Feature matrix comparison

The NanoBSD configuration file is a shell script, and BSDRP uses a heavily customized NanoBSD configuration file generated by a wrapper (`make.sh`).

The migration challenges from NanoBSD to Poudriere image are summarized here:

| BSDRP customized NanoBSD usage | Poudriere image | Purpose |
|:---|:---|----|
| Supports different `src.conf` files: one for buildworld and another for installworld | One `src.conf` is used for both buildworld and installworld; `image-JAILNAME[-SET]-src.conf` is added for installworld/delete-old. The `-X exclude_list` can also be used. | Using `WITHOUT_INCLUDES` or `WITHOUT_DEBUG` for installworld only, not for buildworld |
| Download a specific source revision of stable/releng/head | Use `svn url@rev` (or a custom source tree with `-b -m src=/usr/src`), or use branches | Reproduce the same build on different systems |
| Build a specific kernel file | Install the custom kernel into the custom source tree | Customized kernel |
| Build only a specific list of kernel modules | Declare `MODULES_OVERRIDE` in `-src.conf` | Customized module list |
| Advanced scripting for building non-port software | Create a port instead | Need to build some of `/usr/src/tools` |
| Advanced tuning of the final image | `-A` post-script and `-B` pre-script | Generating an mtree (for host IDS), creating specific users |
| Builds ports using its own (outdated) embedded script | Native role of Poudriere | Adding ports to the image |
| System upgrade by switching the MBR active flag on the system partition | System upgrade by setting the "bootonce" attribute on the system partition (and removed from the older one?) | Upgrading the new/old system partition |

## Customized Poudriere image for BSDRP

How to configure Poudriere to generate a BSDRP firmware image.

### Configuration files

To reproduce the highly customized BSDRP firmware image, several configuration files are needed.

Poudriere requires both a jail and a port tree, so the names are prefixed with `j` and `p` to avoid confusion:

- `BSDRPj` for the jail name
- `BSDRPp` for the port tree name

Start by creating a set of configuration files, prefixed with `BSDRP-`:

- `poudriere.d/BSDRPj-src.conf`: all `src.conf` parameters used for the reference jail buildworld/installworld
- `poudriere.d/BSDRPj-make.conf`: all common port parameters (and port build options)
- `poudriere.d/image-BSDRPj-src.conf`: parameters added for installworld (followed by a `delete-old`)

You also need:

- `BSDRP-pkglist`: list of packages to be built and included in the final image
- A kernel configuration file: this uses the [BSDRP amd64 configuration](https://github.com/ocochard/BSDRP/blob/master/BSDRP/kernels/amd64)
- `excluded.files`: list of files to exclude during installworld
- [`overlaydir/usr/local/etc/pkg.conf`](https://github.com/ocochard/BSDRP/blob/master/BSDRP/Files/usr/local/etc/pkg.conf): includes a `FILES_IGNORE_GLOB` list that prevents specific files from being extracted during package installation

#### poudriere.d/BSDRPj-src.conf

Copy into this file the contents of the `CONF_BUILD` and `CONF_WORLD` variables from the NanoBSD configuration file [BSDRP/BSDRP.nano](https://github.com/ocochard/BSDRP/blob/4febbb26dad24a38275eba344b85f05bc123e59f/BSDRP/BSDRP.nano).

Note that this jail is used to build the ports, so the compiler must be kept available here.

The [BSDRPj-src.conf](https://github.com/ocochard/BSDRP/blob/master/poudriere.etc/poudriere.d/BSDRPj-src.conf) is on GitHub.

#### poudriere.d/image-BSDRPj-src.conf

This file lets you add `WITHOUT_` knobs that are applied during installworld into the final image.

This is where the compiler and other components no longer needed are removed.

The [image-BSDRPj-src.conf](https://github.com/ocochard/BSDRP/blob/master/poudriere.etc/poudriere.d/image-BSDRPj-src.conf) is on GitHub.

#### poudriere.d/BSDRPj-make.conf

This file contains the build parameters for the ports.

The [BSDRPj-make.conf](https://github.com/ocochard/BSDRP/blob/master/poudriere.etc/poudriere.d/BSDRPj-make.conf) is on GitHub.

#### BSDRP-pkglist

This file lists the packages to be built and added to the final image.

The [BSDRP-pkglist](https://github.com/ocochard/BSDRP/blob/master/poudriere.etc/poudriere.d/BSDRP-pkglist) is on GitHub.

#### excluded.files

List of files and directories that `WITHOUT_` knobs were not able to keep out of the final image.

The [excluded.files](https://github.com/ocochard/BSDRP/blob/master/poudriere.etc/poudriere.d/excluded.files) is on GitHub.

#### Files excluded from packages

When customizing port options, some files cannot be disabled. `pkg` can be configured to skip extracting specific files from packages during installation.

The [customized pkg.conf](https://github.com/ocochard/BSDRP/blob/master/BSDRP/Files/usr/local/etc/pkg.conf) is on GitHub.

### Building the jail

The simplest approach is to reuse the existing patched BSDRP source tree: specific kernel configuration files can be installed into it and used afterwards.

Start by patching the BSDRP sources (system sources and ports) using the [BSDRP Makefile](https://github.com/ocochard/BSDRP/blob/master/Makefile):

```
make patch-sources
```

Two patched source trees are now ready:

- `obj/FreeBSD` (includes the BSDRP-specific kernel configuration file)
- `obj/ports`

<!-- -->

```
poudriere jail -e poudriere.etc -c -j BSDRPj -b -m src=obj/FreeBSD -K amd64
```

Command-line details:

- `-b`: build from source
- `-c`: create a jail
- `-j`: short name for the jail (we cannot use `BSDRP-amd64-10.3R` here, since long names later produce long directory names that are not well supported)
- `-e`: load all configuration files from `./poudriere.etc`
- `-m src=`: path to the patched source branch we want to use
- `-K`: the kernel configuration file (copied here while patching the BSDRP source tree)

### Creating the port tree

Now create a port tree using the existing patched port tree:

```
poudriere ports -e poudriere.etc -c -p BSDRPp -m null -M obj/ports
```

### Build packages

This is Poudriere's native role: give it the jail name, the port tree name, and the list of packages.

```
poudriere bulk -e poudriere.etc -j BSDRPj -p BSDRPp -f /usr/local/etc/poudriere.d/BSDRP-pkglist.common
```

### Generating the firmware image

Build a 2 GB image using the previous sets, jail, and port tree:

```
poudriere image -t firmware -s 2g \
    -j BSDRPj -p BSDRPp -n BSDRP -h router.bsdrp.net \
    -c BSDRP/Files/ \
    -f poudriere.etc/poudriere.d/BSDRP-pkglist \
    -X poudriere.etc/poudriere.d/excluded.files \
    -A poudriere.etc/poudriere.d/post-script.sh
```

Command-line explanation:

- `-s`: size of the full image (matching the flash media)
- `-j`: the jail just generated
- `-p`: the Poudriere port tree whose packages we just built
- `-n`: image name, also used as the partition name
- `-h`: hostname configured on the image
- `-c`: directory tree to be copied onto the image (should include a `pkg.conf` with the `FILES_IGNORE_GLOB`)
- `-f`: list of packages to install on the image
- `-X`: list of files to exclude from installworld
- `-A`: post-script executed at the end for final image tuning (such as generating an mtree)
