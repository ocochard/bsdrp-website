# BSDRP website — project notes for Claude

This is the mkdocs-material site that replaced the original DokuWiki at
`bsdrp.net`. Content was migrated from a DokuWiki backup at
`~/bsdrp-dokuwiki/bsdrp.net/`. The migration plan and rationale live in
`CONVERSION_PLAN.md`.

## Repo layout

```
docs/                — mkdocs content (generated by scripts/convert.sh)
  index.md           — homepage (generated from bsdrp.txt)
  assets/            — favicon, logo, page images
  documentation/     — User guide, FAQ, technical-docs, examples
  community/         — mailing lists, how to contribute
mkdocs.yml           — site config + full nav (hand-curated)
scripts/             — DokuWiki -> mkdocs conversion pipeline
  convert.sh         — orchestrator (idempotent; safe to re-run)
  postprocess.py     — pandoc post-processor (main converter)
  build_htaccess.py  — emits the .htaccess redirect map
  dw_paths.py        — shared id <-> path/URL helpers (see below)
.htaccess            — Apache 301 redirects from old DokuWiki URLs (generated)
site/                — mkdocs build output (gitignored)
```

## Source of truth: depends on migration phase

The DokuWiki backup at `~/bsdrp-dokuwiki/bsdrp.net/` and the conversion
scripts in `scripts/` are **one-shot migration tooling**. The plan is to
discard the backup once the migration is signed off.

- **During migration** (now): the DokuWiki backup is the source of truth.
  Re-running `./scripts/convert.sh` wipes `docs/*.md` and rebuilds it.
  For content fixes, edit the `.txt` file in the backup and re-run.
- **After sign-off**: `docs/*.md` becomes the source of truth. Edit
  markdown directly. The DokuWiki backup and `scripts/` directory can
  be deleted (or kept as historical reference, not as a regeneration
  source).

If you're reading this **after sign-off** and notice the backup still
exists: ask before re-running `convert.sh` — it will overwrite any
direct edits to `docs/*.md`.

## `dw_paths.py` is the single source of truth

The mapping from a DokuWiki id (e.g. `documentation:examples:pf_and_carp_lab`)
to:
  - filesystem path:  `documentation/examples/pf-and-carp-lab.md`
  - public URL:       `/documentation/examples/pf-and-carp-lab/`
  - relative .md ref: `../examples/pf-and-carp-lab.md` (varies by source)

…all lives in `scripts/dw_paths.py`. Both `postprocess.py` and
`build_htaccess.py` import it. **Changing slug rules in one place affects
the other** — link rewrites and redirect URLs must stay consistent or
external bookmarks will silently break.

`DROP_NAMESPACES = ("fr", "wiki", "playground")` — these pages are not
converted; the htaccess redirects them all to `/`.

## Pipeline ordering in `convert_one()`

```
pandoc -f dokuwiki -t gfm
  -> fix_indented_code        # collapse 4-space code into ``` fences
  -> convert_notes            # <note ...> -> !!! admonition
  -> fix_bold_escapes         # unescape \*, \_
  -> normalize_self_links     # http://bsdrp.net/foo -> relative .md
  -> fix_leftover_dw_links    # any surviving [[...]] -> markdown link
  -> drop_home_logo           # bsdrp homepage only
  -> rewrite_links_and_images # all [text](dw-id) -> relative .md / asset
  -> extract_title            # lift H1 into front-matter
  -> build_frontmatter        # prepend YAML front-matter
```

Order matters:
- `convert_notes` must run before `fix_bold_escapes` (it matches the escaped
  `\<note\>` form pandoc emits, then fix_bold_escapes drops the backslashes).
- Self-link normalization runs first so the link rewriter sees consistent
  internal targets.
- `extract_title` must run before front-matter is built so the H1 ends up
  in `title:`.

## mkdocs-native conventions in use

- **Relative `.md` links** — internal links are emitted as relative paths
  (e.g. `../examples/foo.md`). mkdocs validates them at build time with
  `mkdocs build --strict`, which we keep clean.
- **Native mermaid via `pymdownx.superfences`** — *not* the `mkdocs-mermaid2`
  plugin. Mermaid diagrams use fenced ` ```mermaid ` blocks.
- **Admonitions** — DokuWiki `<note>`/`<note important|warning|tip>` become
  `!!! note` / `!!! info "Important"` / `!!! warning` / `!!! tip`.
- **Kebab-case heading slugs** — mkdocs auto-generates kebab anchors;
  DokuWiki's legacy snake_case fragment links are converted via
  `_kebab_anchor()` during link rewriting.

## Common operations

```sh
# Strict build (verifies all internal links and front-matter)
mkdocs build --strict

# Local preview
mkdocs serve
```

During migration only:

```sh
# Regenerate everything from the DokuWiki backup (overwrites docs/*.md!)
./scripts/convert.sh
```
